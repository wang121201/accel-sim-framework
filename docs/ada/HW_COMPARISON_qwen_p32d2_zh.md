## 三、逐项分析

### 3.1 ✅ DRAM 读流量：+0.32%（优秀）

模拟 9.270 GB vs 硬件 9.240 GB，误差 **+0.32%**。

这是**最强的正面结果** —— 说明：
- trace 驱动的访存地址序列**正确**
- L2 → DRAM 的读路径建模**准确**
- 写路径修复**未影响读流量**（与修复前逐位一致）

### 3.2 ✅ L1 store 扇区：-0.000%（逐位精确）

3,701,033 vs 3,701,035（差 2）。**store 指令的扇区计数完全正确** ——
这也印证了写路径修复后 store 被正确识别和下发。

### 3.3 ✅ L1 load 命中：-1.66%（优秀）

124.67M vs 126.77M。L1 命中判定与硬件高度一致。

### 3.4 🟡 L1 load 扇区：-12.17%（偏低）

409.37M vs 466.09M，**少 12%**。

**原因**：模拟器的 L1 扇区计数口径与 NCU 略有差异：
- NCU `l1tex__t_sectors_pipe_lsu_mem_global_op_ld` 统计**每个 warp 的扇区请求**
- 模拟器在 trace-driven 模式下按 trace 记录的地址计数
- 部分被合并（coalesced）的请求在两侧计数方式不同

> 注：**命中数却只差 1.66%** —— 说明差异主要在**未命中的扇区计数**上，
> 而非命中判定逻辑。

### 3.5 🟡 L2 读扇区：-20.05%（偏低）

271.29M vs 339.32M。

**原因**（已在 `METRIC_DETAIL_REPORT_zh.md` 记录）：
模拟器的 `SECTOR_MISS` 只统计**首次 miss 的扇区**，
**不计 MSHR 合并前的重复扇区请求**，而 NCU 统计全部发往 L2 的读扇区。

### 3.6 🔴 L2 读 lookup miss：-74.91%（显著低估）

72.42M vs 288.60M，**少 3/4**。

**这是最严重的偏差**。含义：模拟器认为 L2 的**读未命中率远低于硬件**。

验证：
- 模拟器 L2 读 miss 率 = 72.42M / 343.76M = **21.1%**
- 硬件 L2 读 miss 率 = 288.60M / 339.32M = **85.1%**

**根因分析**：模拟器的 L2 命中率被**高估**。可能原因：
1. **L2 容量/相联度建模**：模拟器 40 MB / 16-way / 1024 set，
   若替换策略过于乐观（如 LRU 完美），命中率会偏高
2. **`indexing=0` 的补偿性近似**：线性映射可能让地址分布更"集中"，
   产生虚假的局部性
3. **MSHR 合并**：模拟器不建模有限 MSHR 并发（参照文件 `limits` 也提到这点）

> ⚠️ 这是**独立于写路径修复的既有问题**（修复前也存在）。

### 3.7 🔴 DRAM 写流量：+150%（显著高估）

182.25 MB vs 72.88 MB。

**这是写路径修复带来的新偏差**：
- 修复前：模拟写 = 0（**漏掉全部写**）
- 修复后：模拟写 = 182 MB（**高估 150%**）

**方向反转，但都偏离硬件**。说明：
- 修复**恢复了写回机制**（正确）
- 但**淘汰频率过高** → 写回过多

**与 3.6 的关联**：L2 读 miss 被低估 75% 而写回被高估 150% ——
两者都指向 **L2 替换/淘汰策略与真实 Ada 不一致**。

## 五、结论与后续

### 5.1 表现总结

| 层级 | 表现 |
|---|---|
| **DRAM 读** | ✅ **优秀**（+0.32%）|
| **L1** | ✅ 良好（store 精确，hit -1.66%，load 扇区 -12%）|
| **L2** | 🔴 **差**（读 miss -75%，读扇区 -20%）|
| **DRAM 写** | 🔴 **差**（+150%）|

### 5.2 核心问题：L2 替换/淘汰策略

**三个偏差指向同一根因**：
- L2 读 miss 低估 75% → L2 命中率被高估
- DRAM 写高估 150% → 淘汰过于频繁
- L2 读扇区低估 20% → 扇区计数口径

**这与之前微基准分析（`l2train` 多余写回）的结论一致** ——
**L2 组映射/替换策略与真实 Ada 不一致**。

### 5.3 建议

1. **优先排查 L2 替换策略**：为何模拟器 L2 命中率远高于硬件？
   - 检查 `l2_cache_config` 的 set/way 映射
   - 检查 `indexing=0` 是否引入了虚假局部性
   - 对比 `indexing=2`（官方）下的 L2 miss 率
2. **验证 MSHR 建模**：参照文件 `limits` 明确指出"未建模有限 MSHR 并发"
3. **扇区计数口径对齐**：模拟器需统计 MSHR 合并前的扇区请求

### 5.4 诚实声明

- 本对比的**硬件侧准确度未自动验收**（参照文件 `hardware_accuracy_accepted: false`）
- 参照文件建议**不要混合 whole/Decode/steps 三个 scope 到一个误差分母**
- 本报告只用 `whole` scope（1030 launches，与我的运行精确对齐）
